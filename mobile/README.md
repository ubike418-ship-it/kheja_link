# Kheja_Link — Mobile

The Flutter app for **Kheja_Link**, the rental-discovery platform for Meru, Kenya.

It talks to the **same Supabase project** as the web app in the repository root, so a
listing published on the web appears in the app immediately, and a home saved on the phone
shows up on the website under the same account.

---

## Getting started

```bash
cd mobile
cp .env.example .env        # then fill in your Supabase URL and anon key
flutter pub get
flutter run
```

### Environment

| Variable | What it is |
| --- | --- |
| `SUPABASE_URL` | Your project URL, e.g. `https://xxxx.supabase.co` |
| `SUPABASE_ANON_KEY` | The anon / public key |

`.env` is read at runtime and is **git-ignored**. For release builds, prefer compile-time
values so no credentials sit in an asset file:

```bash
flutter build apk --release \
  --dart-define=SUPABASE_URL=https://xxxx.supabase.co \
  --dart-define=SUPABASE_ANON_KEY=your-anon-key
```

`--dart-define` takes precedence over `.env` when both are present.

> Only ever the **anon** key. Row Level Security is what protects the data. The
> `service_role` key must never go into an app binary — anyone can extract it.

### Supabase setup

The database is shared with the web app, so if you have already run
[`../supabase/setup.sql`](../supabase/setup.sql) there is nothing more to do.

For email confirmation and password resets to return to the app, add this to Supabase →
**Authentication → URL Configuration → Redirect URLs**:

```
ke.co.khejalink://login-callback
```

## What the app does

| Screen | What it does |
| --- | --- |
| **Home** | Hero, category rail (the mobile form of the web circular menu), and the newest listings. Pull to refresh. |
| **Search** | Full-text search plus filters — house type, area, bedrooms, max rent, amenities, furnished, premium — and sorting. Infinite scroll. |
| **Property** | Photo gallery, key facts, description, amenities, location with a Maps hand-off, the landlord card, the contact unlock (one price per listing, paid by M-Pesa in the app), and a message to Kheja_Link. |
| **Saved** | Your shortlist. Private to you at the database level. |
| **Account** | Sign in and sign up (with the seeker/landlord choice), profile editing, and for landlords: their listings and their inquiries inbox. |

Messaging Kheja_Link about a listing works **without an account** — the database permits an
anonymous insert into `inquiries` (addressed to the admins) but never an anonymous read, so the
details entered are visible only to Kheja_Link and the sender. Signed-in senders get the reply
in their Inbox.

## Architecture

```
lib/
├── main.dart                    Bootstraps Supabase, handles a missing config
├── config/
│   ├── theme.dart               The Kheja_Link design language, light and dark
│   └── supabase_config.dart     Credentials, .env or --dart-define
├── models/models.dart           Dart mirrors of the database schema + formatting
├── services/kheja_api.dart      Every read and write, and error humanising
├── screens/                     One file per screen
└── widgets/                     Brand mark, property card, loading/empty/error states
```

**Authorization is not implemented in this app.** It lives in Row Level Security on the
database, exactly as it does for the web client. The app asks for what the user should be
able to see; Postgres decides what comes back. That means a tampered build cannot read
another user's saved homes, another landlord's inquiries, or anyone's unpublished drafts.

## The app icon

The launcher icon is the official Kheja_Link logo at
[`assets/branding/logo.jpeg`](assets/branding/logo.jpeg) — **not** the default Flutter icon,
which has been removed from the project.

Icons are generated by `flutter_launcher_icons`, configured at the bottom of `pubspec.yaml`.
If you ever replace the logo file, regenerate them with:

```bash
dart run flutter_launcher_icons
dart run flutter_native_splash:create
```

Android uses an adaptive icon whose background (`#1B2430`) is matched to the logo's own dark
ground, so it sits correctly in circular, squircle and rounded-square masks rather than
showing white corners.

## Building

```bash
flutter build apk --release          # Android APK
flutter build appbundle --release    # Google Play
flutter build web --release          # Web
flutter build ipa --release          # iOS (needs macOS)
```

Release Android builds are currently signed with the debug key. Before publishing to Play,
create an upload keystore and add `android/key.properties` — see
<https://docs.flutter.dev/deployment/android#signing-the-app>.
